# Agent Note: 模型能力元数据先于模型环境

Status: implemented

[English](2026-09-03-model-capability-catalog.md) | 中文

## 问题

模型选择器可以选择提供方、模型和推理强度，但 harness 无法告诉环境解析器某个精确模型路由实际使用什么线上协议或状态策略。把 OpenAI Responses 与 DeepSeek chat-completions 当成等价实现，会让后续原生状态和压缩功能宣称适配器尚未实现的行为。

## 决定

`dsh-llm` 现在接受由各适配器拥有的可选精确模型能力元数据。记录标识线上协议、状态策略、提示缓存所有权、原生压缩、后台执行和并行工具调用支持。`LlmRuntime` 校验并分离该记录，Session Controller 通过现有模型目录投影它。

DeepSeek 直连适配器报告自己的 chat-completions 传输和当前客户端回放实现。pi-ai 适配器报告每个已解析的 pi-ai API 以及当前客户端回放实现。在这些行为具备持久化回放和生命周期支持之前，两个适配器都不会宣称提供方管理的状态、原生压缩或后台执行。

本元数据只用于描述，不会在本次变更中改变请求派发、增加会话事件或改变模型选择。

## 曾考虑的替代方案

- **在 Session Controller 中推断协议和能力**——不采用，因为精确路由由适配器拥有，只有适配器知道其派发路径实现了什么行为。
- **立即新增独立的模型环境包**——延期，因为环境需要能力元数据与选中的 AgentPreset／任务策略共同决定；在原生协议行为之前加入注册表会产生第二个事实来源。
- **把所有提供方特性都暴露成布尔值**——不采用，因为提供方支持某项能力不代表已安装适配器实现了它。字段描述已安装的行为，而不是提供方的宣传能力。

## 影响

模型环境工作现在可以消费稳定且经过校验的目录记录，无需探测提供方或复制适配器知识。第三方适配器省略可选字段时保持兼容。当前目录没有原生 Responses 续接、压缩条目或后台任务，因此这些能力仍需单独的持久会话和适配器变更。

## 测试

LLM 服务测试覆盖有效元数据的分离、字段省略和无效值。DeepSeek 直连、pi-ai Responses 以及 Host catalog 测试覆盖内置声明与投影。
