# Agent Note: 记录私人二次开发

Status: implemented

[English](2026-09-04-custom-harness-distribution-documentation.md) | 中文

## 问题

仓库入口文档将代码标为 `alpha.5`，并且只介绍模型环境工作，因此读者无法确认当前私人二次开发版本及其增加的能力。

## 决定

根 README 将本仓库标识为基于官方 DeepSeek Harness 的私人二次开发，记录当前代码线为 `0.1.2-rc.1`，单独记录 Windows 桌面目录目标版本 `3.0.0`，并维护一份带源码链接的新增 Web 外壳、本地界面能力、局域网共享、外部服务工作台、产品 bundle、jailbreak 评测和模型环境回放清单。更新报告记录相同版本事实。

清单区分仓库内已实现的能力、需要独立运行本地服务的面板以及需要配置外部数据源的面板。官方 Harness 的架构、权限、沙箱策略和审批行为仍是本私人二次开发的基础。

## 曾考虑的替代方案

- **保持根 README 简短，只依赖源码树**——不采用，因为仓库树不会告诉用户哪些行为是本地增加的、由哪个服务负责，或某个面板是否需要外部依赖。
- **继续使用 `alpha.5` 作为当前产品标识**——不采用，因为当前代码线和根包元数据都是 `0.1.2-rc.1`，而 `alpha.5` 是较早的本地标识。
- **把完整实现文件清单复制到 README**——不采用，因为带源码链接的能力分组足以用于定位，而详细契约仍由各包 README 和源码负责。

## 影响

用户可以从仓库入口页识别私人二次开发增加的能力和当前版本。产品界面或外部集成变化时需要同步更新清单；实现细节仍以包契约和源码行为为准。`AGENTS.md` 的常驻预算设为 2,150 个词，因为其中的用户范围限制和知识前置要求是每项维护任务都需要的上下文。

## 测试

修改过的双语配对通过 `verify-translation-pairing --write` 重新记录；已运行文档门禁和空白字符检查。定制源码树中已有的违规项仍使仓库级 lint 无法通过。
