# Agent Note: 启动更新会恢复已验证的发布合并并限制桌面端等待时间

Status: implemented

[English](2026-09-02-startup-update-resume-and-timeout.md) | 中文

## Problem

本地构建更新器可能在 `.git\MERGE_HEAD` 中留下已解决的发布合并，导致后续每次启动都报告更新被阻塞，即使已经没有未解决文件。变更过的 `pnpm-lock.yaml` 也可能阻止 `git merge --abort` 完成恢复。桌面启动器没有持久化更新日志，并且可能无限等待失去响应的 PowerShell 子进程。

## Decision

启动更新器会在工作树没有未解决文件、且待提交合并准确对应 `dsh-v*` 发布标签时，将 `.git\MERGE_HEAD` 视为可恢复状态。未解决的合并和非发布合并头仍会保持阻塞。恢复流程会在 `git merge --abort` 前后保护用户修改过的 `pnpm-lock.yaml`，然后重新构建工作树，再报告失败。

桌面启动器会以 15 分钟的有限等待时间运行更新器，把 stdout 和 stderr 记录到用户数据目录，超时后终止 PowerShell 进程树。更新退出码非零时，启动器会记录可诊断警告并继续启动服务；更新器状态文件保留可操作的失败原因。

## Alternatives considered

**阻止所有带有 `MERGE_HEAD` 的状态。** 已否决，因为冲突已经解决的合并可以安全验证并提交；永久阻止会把可恢复的中断更新变成必须手工修复的任务。

**使用 reset 或强制清理丢弃工作树。** 已否决，因为定制 harness（运行框架）包含本地 UI 和桌面端适配，启动恢复必须保留用户工作和本地修改。

**无限等待并依赖控制台输出。** 已否决，因为桌面进程没有可靠的交互式控制台，卡住的更新可能阻止应用打开。文件日志和状态记录让启动器继续后仍能诊断失败。

## Consequences

- 已解决的发布合并可以在下一次启动时完成；未解决或异常的合并仍会明确失败并受到保护。
- 锁文件恢复路径会保留用户内容，但更新失败时状态文件仍是下一次修复尝试的依据。
- 桌面启动的更新等待时间有限，持久化日志位于用户数据目录。
- 本地 checkout（检出目录）已验证为 `dsh-v0.1.2-alpha.5`；后续发布标签使用相同的恢复和验证路径。

## Testing

启动更新器已完成 alpha.4 恢复和 alpha.5 升级。`pnpm run build` 已完成，本地适配测试通过 `83/83` 和 `378/378`，桌面主进程语法检查已通过。桌面快捷方式解析为以桌面主进程为参数的 Electron；最终更新状态为 `updated`，当前版本和最新版本均为 `dsh-v0.1.2-alpha.5`。
